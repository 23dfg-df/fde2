# 样本与评测说明

本次数据集 `fde-doc-synthetic-v1` 包含 6 张原创、程序生成的 PNG 文档，尺寸均为 1200×1600 像素。它们用于验证“图片输入 → 模型解析 → 结果留存 → 规则评测”的工程流程，不含私人文档，也不代表真实业务数据的难度分布。

## 先做一个预测

在运行模型前，先写下你认为最容易出错的两页，以及可能出现的错误。提示：区分识别错误、阅读顺序错误、表格结构错误和格式差异。运行后保留你的预测与实际结果，不要只保存模型答对的页面。

## 六页样本分别检验什么

| ID | 样本 | 规则评测 | 需要人工补查的部分 |
|---|---|---|---|
| sample-01 | 中文资源使用通知 | 逐字参考与 CER | 操作条件是否遗漏、句子是否重复 |
| sample-02 | 英文推理服务手册 | 逐字参考与 CER | 编号与标点、行尾单词是否完整 |
| sample-03 | 中英混合资产表单 | 8 个字段值的词面覆盖 | 字段和值是否配对正确，不能只看值出现了没有 |
| sample-04 | 4 行×4 列资源表格，包含表头 | 16 个单元格正文覆盖、HTML 表格存在性 | 行列关系、表头、顺序；这些不是仅靠覆盖率就能确定的 |
| sample-05 | 双栏阅读顺序 | CER，参考顺序为完整左栏后完整右栏 | 是否按左右交错逐行输出、是否串栏 |
| sample-06 | 小字、低对比度、近似字符 | CER | O/0、I/l/1、小数点、日期与编号顺序 |

所有页面都明确标有“合成教学样本”或英文对应文字，该文字也包含在参考文本中。页内没有未计入参考的页码、装饰性页脚或隐藏文字。背景色、表格边框和分隔线不是文字标签。

## 参考答案从哪里来

`samples/build_samples.py` 先定义文字，再用 Pillow 生成全新页面。绘制文字时，脚本同步记录每一段可见文字和边界框，写入 `samples/manifest.json`：

- `reference_text`：按明确阅读顺序连接的全部可见文字。
- `expected_fields`：表单需要出现的字段值；键名只用于解释匹配结果。
- `expected_cells`：表格单元格正文的扁平列表，保留重复次数。
- `expected_table`：人工复核用的 4×4 单元格矩阵。
- `visible_text_boxes`：生成图片时记录的文字边界，供定位与排查。
- `sha256`：对应 PNG 的文件哈希。

程序生成的参考是固定标签，不是由待测模型生成的答案。样本没有用于训练模型；若以后用这些页面微调，就应另建未参与训练的测试集，不再把这 6 页的成绩作为独立测试成绩。

## 怎样解释 CER

字符错误率 CER 由最小编辑距离计算：插入、删除、替换次数之和，除以参考文本长度。数值越低越好；输出有很多多余字符时可以超过 100%，不能强行截断为 100%。

全文 CER 只对 `structured_parse`（纯文本识别）任务计算。官方 `doc_parse` 提示要求忽略页眉页脚，与包含全部可见文字的参考不一致，此时平台不输出 CER，不能把按提示省略的内容误判成识别失败。

本平台的文本归一化口径由后端实现决定，当前约定是 Unicode NFKC 归一化并去除空白。标点和 Markdown 标记不应悄悄忽略。因此，模型输出多了标题符号等结构标记时，也可能增加文本 CER；应结合原文和输出解释，不能把一个数字当作纯字符识别能力的完整结论。

双栏样本的 CER 还会反映阅读顺序。两栏都识别正确但顺序错误，仍可能得到较高 CER。这样的结果应记录为阅读顺序问题，而不是简单说“汉字都识别错了”。

## 表单和表格怎样评分

资产表单仅统计字段值是否在归一化输出中出现。例如 `DOC-LAB-031` 出现了，就满足对应字段的词面覆盖条件，但这不能证明它与“资产编号”保持正确对应。短值如 `6` 容易偶然出现，所以必须结合其他字段和人工复核。

表格样本不能直接把原始 HTML 与普通段落做 CER 对比。后端仅抽取 HTML 的 `td/th` 正文检查单元格覆盖，并单独报告是否存在 HTML 表格。如果只输出包含所有单元格文字的一段话，没有 `td/th` 标签，当前单元格覆盖会是 0。即使覆盖达到 100%，行列顺序、合并关系仍可能错误，必须看图复核。

**本次没有实现完整的表格结构相似度评测或独立人工语义审核。** 不应将字段覆盖率、单元格覆盖率或 HTTP 成功率改称“业务准确率”。

## 怎样复建图片

在有 Pillow 和中文字体的环境中，从项目目录执行：

```bash
python samples/build_samples.py
```

脚本会在 macOS 自动查找 STHeiti 字体，在 Linux 尝试 Noto Sans CJK 或文泉驿字体。也可以指定字体：

```bash
python samples/build_samples.py \
  --font /path/to/chinese-regular.ttf \
  --bold-font /path/to/chinese-bold.ttf
```

这会重新生成 6 张图片与清单。不同字体可能改变字宽、换行和图片哈希，因此复建后应以新清单记录字体与样本版本；不要混用旧运行报告。服务器使用已经生成的 PNG 做推理时，无需安装这些制图字体。

## 本轮验收边界

样本生成、尺寸、哈希、文字边界和参考标签可以直接检查。只有真实模型运行后才能评价识别结果。助手生成样本和实现评测不等于学习者已经掌握；请自己解释至少一条错误及其所属环节。
