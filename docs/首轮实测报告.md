# 首轮实测报告：2026-11-16

本报告记录 2026-11-16 的历史工程验收，不包含个人学习表现。数据来自固定版本的腾讯 HunyuanOCR 在实验室物理 GPU 1 上的真实请求；没有用预先填写的答案替代模型响应。

## 条件与结果

模型提交为 `47644ecc4fc854efa4f505155158831f36773ee4`。vLLM 0.18.1、PyTorch 2.10.0、Transformers 4.57.6，BF16，eager 模式，8192 上下文、同时 1 个请求。每页最长边 1600px，本次 `max_tokens=2048`，temperature=0，repetition_penalty=1.08。

共 5 个任务、8 次页面解析全部正常结束，均返回 `finish_reason=stop`：6 个独立合成样本、1 个 PDF 上传样本、1 次中文通知复跑。

完整记录：`evidence/acceptance-summary.json`；每个任务也有单独 JSON，可与工作台任务 ID 对应。

## 分数背后的差异

全文 CER 采用 NFKC 后删除空白、保留标点与格式符号的口径。多加 Markdown 标记会增加 CER，这不等价于把汉字看错。低对比样本还出现了大写 `I` 和小写 `l` 的实际混淆，说明这套页面有能力暴露识别错误。

字符差异记录在 `evidence/text-differences.json`。学习时先完成第一课的原图核对，再看此文件；不要修改参考来追求低分。这里没有报告所谓“99% 企业准确率”。

表单 8/8 表示 8 个预期值都出现了，不能证明值与字段关联正确。表格 16/16 表示预期 HTML 单元格内容都被匹配，不能证明任意复杂表格、合并单元格或排版都能处理。现有样本仅是干净、可重建的教学材料。

上传 PDF 确实经过 `/api/uploads`、PyMuPDF 栅格化和真实模型请求；平台没有自动为上传内容编造参考标签，也未把 PDF 内嵌文本直接冒充模型输出。
