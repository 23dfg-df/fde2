# 隔几天回来，怎样继续学习

先选择当天唯一的小任务，不必一次重装环境或复跑全部样本。

## 练习与提示

本次目标：用 `sample-06`“小字与近似字符挑战”完成提交、查询和原图核对。

1. 在自己的服务器或本地环境中检查模型状态；原有任务历史可用于对照。
2. 查看原图，预测哪类字母、数字或编号最可能出错。
3. 沿用 `structured_parse` 与 `max_tokens=2048`，只把页面编号改为 `sample-06`。
4. 获得本次任务 id 后，查询它的最终结果。任务的 `queued`、`running`、`completed` 含义不同。
5. 对照图片记录一处字符差异；没有发现差异就明确写“未发现”，不要为了交作业制造错误。

提交证据：请求参数、任务 id、原始输出、CER、自己找到的差异和一句解释。先自己完成，再阅读历史实测差异文件。

## 恢复环境时查什么

源码、脚本和历史证据可以从仓库重新获取；新推理需要自己的 GPU 服务。GitHub 上能读到页面不等于服务器上的模型正在运行。

- 环境仍在：按 README 启动模型与应用，等待 `model_ready` 为 true。
- 仅有应用：可以浏览样本和历史；新推理需要启动独立 vLLM 模型服务。
- 需要重建：先运行 CPU 检查，再按 README 准备模型环境和权重，核对固定版本。
- 使用专用用户服务：模型单次运行上限为 8 小时；超时退出后，需要按当前资源重新启动。

模型默认使用一张物理显卡。先看当前资源，不假设几天前的空闲显存仍然可用。

## 如何记录掌握程度

把“跟随命令成功”“能解释字段”“能够独立改参数并排障”分别记录。一次成功输出和低 CER 都不能证明已经掌握整个部署系统。

这个练习完成后，再选择下一项：表格结构核验、上传 PDF、失败任务排查或加入自己的带标注文档。每次只做一项并保留证据。
